# 05 — UX

The bar is **top notch**: this is a portfolio piece, so the experience is what people judge. Design happens *as we go*. This doc holds the principles, the per-phase acceptance criteria, and a running design log. Screens get designed at the start of each phase and reviewed before the phase is called done.

## Principles

1. **Trust through traceability.** Every number is clickable and shows where it came from (K-1 box → PDF highlight, note → timestamp, research → citation). Hover shows the source; click opens it. This is the signature interaction.
2. **Show, don't make them wait.** Optimistic UI, skeletons that match the final layout, streaming chat with visible tool steps, and extraction progress shown as named stages ("Reading page 2 · Matching Box 20 codes").
3. **One next action.** Every screen makes the next step obvious (one primary button). Empty states teach the next move and never just say "No data."
4. **Keyboard-first for experts, obvious for first-timers.** ⌘K command palette everywhere, j/k/a/e in review, and a guided tour for demo visitors.
5. **Calm density.** Tax data is dense. Use a strong type hierarchy, tabular numbers, aligned decimals, generous whitespace around the dense parts, and color reserved for *meaning* (status, diff, risk), not decoration.
6. **Honest states.** "Synthetic data," "cached answer," "AI proposal — not applied," "not configured," and "dry run: never sent to IRS" are always visible, styled consistently and never alarming.
7. **Reversible by default.** Edits keep the original, proposals need acceptance, and undo is available for accepts. No destructive action without a confirm step.
8. **Accessible.** WCAG 2.1 AA contrast, full keyboard paths, visible focus, and screen-reader labels on numbers ("Box 1, ordinary business income, one hundred fifty thousand dollars").
9. **Fast.** Screen transitions under 100 ms, first load of the demo under 2 s, and no layout shift.

## Visual system (starting point, refined as we go)

- Base borrowed from Drivkraft: `slate-900` sidebar, `slate-50` canvas, white cards, `slate-200` borders, `blue-600` primary, Geist Sans + **Geist Mono for all figures** (tabular).
- Semantic colors: success `emerald`, warning `amber`, error `rose`, AI/proposal `violet`, source/citation `sky`. Each has light and dark variants.
- Tokens are defined as CSS variables from day one; dark mode ships with v1.
- Motion: 150–200 ms ease-out on state changes, a shared-element transition from a citation chip to the source pane, and nothing gratuitous. Respects `prefers-reduced-motion`.
- Icons: Lucide, one stroke weight.

## Signature interactions (to design and prototype)

| Interaction | Where |
|---|---|
| **Source peek**: hover any figure → a popover with its source snippet and page thumbnail; click → the split view opens at the exact PDF region | Everywhere |
| **Evidence overlay**: PDF page with box highlights color-coded by status; selecting a table row pans and zooms to it | K-1 review |
| **Ledger lens**: toggle to see what the bridge mapped, collapsed or couldn't use, with the dollar amounts at stake | K-1 review, return |
| **Line waterfall**: a return line broken down into contributing K-1s/inputs (Recharts waterfall) | Return view |
| **Scenario diff**: side-by-side base vs. what-if, with changed lines highlighted | Return view |
| **Tool-step chat**: collapsible steps showing each MCP call, then an answer with citation chips | Chat |
| **Proposal cards**: violet cards (from chat, notes or workpaper imports), accepted with ⏎ and rejected with ⌫ | Inbox / notes / diff |
| **Cell diff review**: spreadsheet-style grid with old → new in each changed cell, and conflicts pinned to the top | Workpaper import |
| **Filing timeline**: vertical status timeline; a reject expands to the rule and a "Fix" deep link | E-file |

## Per-phase UX acceptance criteria

| Phase | Done means |
|---|---|
| 0 | App shell, tokens, light/dark, ⌘K stub, polished empty states; Lighthouse accessibility ≥ 95 |
| 2 | Reviewer can take the synthetic K-1 from extracted to approved **with the keyboard only**; source peek works on every figure; extraction progress shows named stages |
| 3 | Any return line explains itself in one click (waterfall); scenario diff readable at a glance |
| 4 | First token < 1.5 s; tool steps visible; every factual sentence carries a citation chip |
| 5–6 | Cached vs. live clearly labeled; proposals accepted in one action, and undo works |
| 7 | Round-trip a changed workbook and review the diff in under 30 s |
| 8 | A reject leads to the right field in one click |
| 10 | A first-time visitor reaches the "aha" moment (click a number → see its PDF source) within 60 s, without instructions; mobile layout works at 375 px for viewing |

## Process

- At the start of each phase: sketch the screens (low-fi), agree on them, then build.
- Before calling a phase done: review against the principles and criteria, test keyboard-only, check dark mode and 375 px, run Lighthouse.
- Usability check at M2 and M5: 2–3 people who haven't seen it, silent observation, note where they hesitate.
